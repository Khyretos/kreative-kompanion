## Lessons (short list; full rows in docs/lessons-learned.md)

1. **Write step 4 into the checklist and tick it with evidence.** Skipping the Coder happened silently in #167 and #168 (lessons 176-177) and then became the default because
   the route was blocked. If pipeline.py cannot run, say "step 4 skipped" in the first reply, not at the end.
2. **Get the Coder route permitted before the queue starts.** One standing permission (`pipeline.py` may use `OVMS_API_KEY` from
   kreative-kompanion/.env) would have kept the measurement alive; instead eight PRs have no Coder data.
3. **The permission layer is the biggest time sink, not review or CI.** Standing allow rules for `git merge`/`push origin HEAD:main`, `tools/deploy.sh`
   and read-only DB reads are worth more than any speed-up in the code.
4. **Run the binary before pushing a route.** `cargo test` missed an overlapping `/capabilities` route in KG-08; starting the server with
   `kompanion.example.toml` caught it.
5. **Never hand-write ledgers.** `review_findings.py` writes them in Prettier layout; a hand-written one failed lint 4 times (KG-02).
6. **Triage, commit the ledger, push and run the gate in one go.** Every push makes PR-Agent re-report the same findings under new ids.
7. **Exclude `docs/qwen-log` from PR-Agent.** Draft rounds in the jsonl made fake "compilation error" findings (fixed for the gate in #172; PR-Agent itself still reads them).
8. **Lesson numbers collide** when two threads add rows (176 and 177 exist twice, KG-02 and KG-03). Re-read the file right before taking a number.
9. **Cumulative thread metrics need the per-task delta written down.** KC-01, KG-04, KG-05 and KG-06 only recorded cumulative totals; the per-PR numbers
   above are derived and marked so. Record the delta at each PR from now on.
10. **A small state machine or a two-halves file is where the Coder fails** (CI-MERGE: cut off at 4,000 tokens, repeated two bugs; STU-C4b: three fix rounds did not converge). Split logic from I/O and give a state table.
11. **Fresh-install and live checks need what the test user owns.** KG-03's live run was impossible because the test user has no paired computer.
