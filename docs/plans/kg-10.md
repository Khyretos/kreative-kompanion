# KG-10: generic project settings

## Change

- Before: only `projects.ptype` (chat/game/programming) and a repo computer + folder for programming projects existed (migration 0017).
  A game project had no repo, build or test settings (M6-10 was still queued); the scheduler's check command and computers were set separately (KG-03).
- `server/src/devsettings.rs` (+ migration 0130 `projects.dev_settings`, JSON): per project preset, engine, build, test, run, deploy
  commands, a screenshot folder (relative, no `..`) and the last result per command. Same fields and same code path for every project type.
  Presets: `software` (make / make test) and `game` (engine kk-engine, `cmake --build build`, `ctest --test-dir build --output-on-failure`,
  screenshots folder); a preset only fills the fields, the user edits and saves.
- API (`devsettings_web.rs`): `GET/PUT /api/projects/{id}/dev-settings` (settings + presets + the repo), `POST /api/projects/{id}/dev-settings/run/{build|test|run}`
  (202 at once; runs as a shell job on the repo computer in the repo folder through the normal grant, so no new rights; the result is
  stored in `last` and a projects event is sent). Deploy is stored and shown to the planner but never started from here.
- Planner: the plan prompt starts with "Repository and commands:" (folder, engine, build, test, run, deploy, screenshots) when anything is set
  (the same KG-02 planner for software and game projects, so M6-11 needs no game-only path).
- Scheduler: when its own config has no computers, the project's repo computer + folder is used; when it has no check command, the test
  command is. Its own values always win; `enabled` is never changed by the settings.
- Web: a "Build and test" form for game and programming projects (preset select, six fields, Save, Build/Test/Run now with the last result);
  game projects now also get the repo form (computer + folder) that programming projects had.
