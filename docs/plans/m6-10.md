KG-10 (PR 181) already built what M6-10 asked for: repo folder and computer, engine, build, test, run and deploy
commands, a screenshot folder, Build/Test/Run from the panel with the last result live. M6-10 became its "game"

`ctest`) that do not build kk-engine from a fresh checkout.

## Change

The game preset now uses kk-engine's own CI commands (`.github/workflows/ci.yml` in kk-engine):

- build: `cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug && cmake --build build -j --target kke_tests starter_game`
- test: `./build/bin/kke_tests`
- run: `cd build/bin && xvfb-run -a -s '-screen 0 1280x720x24' timeout 8 ./starter_game; test $? -eq 124` (the game runs
  headless for 8 s; exit 124 = it ran the whole time, as in kk-engine's smoke test)

The web mock and the Playwright expectation follow. New server test: `the_game_preset_uses_kk_engines_own_ci_commands`.

## Live run (2026-10-24, kireserver, kk-engine main in its CI image kke-ci:1, capped 10 GB / 6 cores)

The preset's three commands on a fresh clone: build 420 s (1533 steps, exit 0), `kke_tests` 250 s (1245 passed,
exit 0). The first headless run started the game from the repo root, so it could not find `shaders/*.spv`, disabled
Models, UI and Scripts and aborted after 1 s on a VMA assert ("Some allocations were not freed") while tearing
down. kk-engine's CI starts the demos from `build/bin`; with `cd build/bin &&` the starter game ran the full 8 s
(exit 124, check passes). The run command now does that. The teardown assert after a failed init is a kk-engine
bug, passed to the kk-engine session.
