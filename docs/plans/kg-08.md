# KG-08: capability matrix and model benchmark

## Change

- `server/src/capmatrix.rs` + migration 0129 (`capability`: provider, model, task type, tried, passed). Task types come
  from the task words (bugfix, tests, docs, refactor, feature). Task runs record each try: a rung that fails a
  model-fixable way counts as not passed, a run that ends done counts as passed for the model that finished it.
- Verdict per model and type: unknown under 3 tries, passes at 80 %+, fails at 40 %-.
- Routing (`taskrun`): if the worker role is known to fail the task's type and a configured `[[ladder]]` rung is known
  to pass it, the run starts with that rung and says why; otherwise nothing changes (the planner makes no model
  choice, so routing sits where the model is picked).
- `GET /api/capabilities` (matrix + text), `POST /api/capabilities/bench` (benchmark results for one model).
- `docs/benchmarks/fixtures.md`: one fixture per type and the command that posts results. A new model gets a matrix
  from one benchmark run (5 fixtures give 1 try per type; 3 runs give verdicts).

## Tests

`cargo test`: 477 pass (7 new): task types from words, verdicts need 3 tries and the 80/40 edges, the router skips a
failing worker only for a passing configured rung, text output, runs and benchmark results are counted in SQLite.

## Not done

The benchmark runner itself (an automated job per fixture on the A770/CI runner) is not built: it needs the
fixture repos and a GPU slot; the ingestion and routing it feeds are built and tested. Live check not done.
