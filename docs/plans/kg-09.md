# KG-09: integration gate

## Change

- `tools/integration_gate.py`: counts merge commits since the tag `gate-ok` (PR number and title from the merge
  subject). When N (`every`, default 5, `.forgejo/integration-gate.json`) are due it runs the configured checks
  (server tests, web tsc, tools tests; a screenshot/playtest script is one more entry) and compares test counts
  with `docs/integration-baseline.json` (a count below the baseline fails). A pass moves `gate-ok` to HEAD. A failure
  keeps the tag and writes `gate-task.json`, an import file with a queued task "Integration gate failed: <checks>"
  whose description has the commit range, the merged PRs in it, the failing output (cut to 1500 chars) and
  "done when the checks pass again".
- `.forgejo/workflows/integration-gate.yml`: runs it on every push to main (full history, tag fetched, tag pushed
  after a pass).

## Tests

`python3 -m unittest tools/test_integration_gate.py`: 7 pass on real temporary git repos: merge counting, due after N,
a pass moves the tag and makes no task, a deliberately broken merge (build exits 3) becomes a task with the exact
`base..head` range, the merged titles and the output, a test count under the baseline fails, the import file shape,
long output is cut.

## Not done

The workflow was not run on the runner (it runs after this merges); importing `gate-task.json` into Kompanion is a
manual `kompanion-server import` step for now. Baseline starts empty (no count rule until a number is added).
